There is currently a single maintainer. Review, merge, and release decisions
are made by that account. See [GOVERNANCE.md](GOVERNANCE.md) for how that
changes when a second maintainer joins.

## What maintainers do

- Triage issues and security advisories
- Review pull requests against the quality gates in [CONTRIBUTING.md](CONTRIBUTING.md)
- Keep credential handling fail-closed
- Cut release-candidate evidence; tagging a release is a separate manual step
- Enforce the [code of conduct](CODE_OF_CONDUCT.md)

## Becoming a reviewer or maintainer

The project is looking for reviewers and co-maintainers with experience in:

- Enterprise identity platforms (Okta, Entra ID, Google Workspace)
- Cloud security posture (AWS, GCP, Azure, OCI)
- Low-code / no-code administration
- SARIF and GitHub code scanning
- Detection engineering for agent frameworks and MCP

Start by contributing documentation, signatures, offline fixtures, tests, or a
connector. Consistent, high-quality work is how reviewer access is earned.

Open an issue or discussion titled `Maintainer interest` if you want to help
share the load.
